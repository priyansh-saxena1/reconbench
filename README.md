# ReconBench

**Does a financial AI agent flag a reconciliation failure — or fabricate consistency?**

ReconBench is a contamination-resistant benchmark for *selective refusal under arithmetic-implied contradiction* in real financial-statement data. Each item presents reported balance-sheet figures and asks the model to verify the accounting identity **Assets = Liabilities + Stockholders' Equity**. Half the items reconcile (correct behavior: confirm and answer); half contain a single perturbed figure that breaks the identity by a margin detectable *only by doing the arithmetic* (correct behavior: flag the inconsistency). A model that confidently confirms a broken balance sheet is committing the exact failure that matters in finance — a fabricated consistency that could pass a cursory audit.

This sits in the white space left by 2026's selective-refusal benchmarks (RefusalBench, AbstentionBench) and financial benchmarks (FAB, Fin-RATE, FinanceBench): those test text-span refusal or final-answer capability, not **numeric reconciliation refusal** scored with an **audit-cost-asymmetric** metric.

## Why it's contamination-resistant
Items are generated by perturbing real SEC figures, so the exact (figures → label) instances exist in no pretraining corpus. The generator is fully reproducible from public data.

## Data provenance & license
- **Source:** 100% U.S. SEC XBRL (`data.sec.gov`), public domain. No FinanceBench (CC-BY-NC) data is used — see `DATA_LICENSE`.
- **Release:** data CC-BY-4.0; code MIT.

## Quickstart
```bash
pip install -r requirements.txt        # only pytest/requests; clients use stdlib
python scripts/make_dataset.py         # pulls live SEC data -> data/*.jsonl
python scripts/run_eval.py --model mock_reconciler   # render -> model -> judge -> results/
python scripts/build_goldset.py        # assemble the judge-validation gold set
python scripts/score_all.py            # Trust Score leaderboard + penalty sweep + CRS foil
# real frontier models (needs a Groq key in the environment):
GROQ_API_KEY=... python scripts/run_real.py --stratified 80   # LLM-judged eval of real models
GROQ_API_KEY=... python scripts/validate_judge.py             # rule vs LLM judge on gold set
python -m pytest tests/ -v             # 54 tests (data, harness, scoring, judge, real models)
```
The SEC client caches `companyfacts` JSON under `data/_cache/` so re-runs need no network. Set a real contact email in `config.USER_AGENT` before heavy use. Real models read their key from an env var only (e.g. `GROQ_API_KEY`); it is never passed as an argument or logged.

## Current dataset (Chunk-1 V0)
427 items (215 reconciling / 212 non-reconciling), 14 large filers, FY2008–2026. All perturbation discrepancies in the arithmetic-only band 0.5%–14.1% (median 1.44%).

## Structure
```
config.py              constants: companies, identity tags, thresholds
src/sec_client.py      SEC XBRL companyfacts pull (stdlib, cached, rate-limited)
src/identities.py      reconciliation check + equity-tag auto-resolution
src/perturb.py         reconciling -> non-reconciling (period-swap / nudge)
src/build_seed.py      join Assets/Liabilities/Equity, keep only exact ties
src/schema.py          LOCKED item schema + validator
src/render.py          provided-context prompt (shared with the eval harness)
src/model_client.py    mock models + real Groq/OpenAI-compatible wrapper (env-key only)
src/judge.py           rule judge (fast/fallback) + wired LLM judge for Chunk 4
src/score.py           audit-cost Trust Score, penalty sweep, CRS foil, ECE
src/judge_validation.py  rule-judge vs human gold-label agreement (kappa, confusion)
scripts/make_dataset.py  orchestrator (live)
scripts/run_eval.py    render -> model -> judge -> categorize -> results/<model>.jsonl
scripts/build_goldset.py assemble the judge-validation gold set (reproducible)
scripts/run_real.py    Chunk-4 driver: real Groq models, LLM judge, cached + resumable
scripts/validate_judge.py  record rule-judge vs LLM-judge agreement on the gold set
scripts/score_all.py   leaderboard across all result files + sweep + CRS differentiation
tests/test_chunk1.py   identity + perturbation + dataset invariants
tests/test_chunk2.py   judge unit + harness discrimination
tests/test_chunk3.py   Trust Score + sweep + CRS foil + ECE + judge validation
tests/test_chunk4.py   real-result schema + caching + reliability + recorded judge val
DATASET_CARD.md        HF-style dataset card (provenance, license, leaderboard snapshot)
STATE.md               resume contract / locked decisions / next action
```

## Roadmap (the funded-fellowship arc)
Eval harness + LLM-judge (Chunk 2) → audit-cost Trust Score + penalty sweep, differentiated from RefusalBench's CRS (Chunk 3) → **real frontier models + validated LLM judge + leaderboard (Chunk 4, done)** → **dataset card (Chunk 5, done; see `DATASET_CARD.md`)** → paper (Chunk 6). Later: agentic retrieval, income-statement & segment identities, temporal/staleness conditions.

**Real-model results so far** (`results/leaderboard.json`, rule-judged over the corpus): qwen3-32b on the **full 427** scores only +0.042 (acc 0.569), false-flagging 68% of controls and fabricating on 18% of broken sheets — a real model the benchmark is far from saturating. The two Llamas (llama-3.1-8b at n=427, llama-3.3-70b at n=323 pending a provider daily-token reset) have **near-identical accuracy** but opposite error types — the 8B over-flags and never fabricates, the 70B fabricates a little (it confabulated $746M of equity to "balance" an Adobe sheet) and never over-flags — so their Trust-Score order **flips with the fabrication penalty** (70B ahead at P_FAB=2, 8B ahead at P_FAB=4). A validated LLM-judged 80-item cross-check is kept under `results/llm_judged_n80/`.
